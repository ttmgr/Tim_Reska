PHP2Shell, the October 2026 PHP flaws and their fix

24 October 2026, Security note

Two critical flaws in the PHP interpreter allow unauthenticated remote code execution on web servers. PHP fixed them on 21 October 2026 by removing the jump-based out-of-memory abort and resetting request-owned state; a third, unpatched flaw followed on 23 October.

This post summarizes PHP2Shell, two critical remote code execution flaws in the PHP interpreter fixed on 21 October 2026, and a related third flaw disclosed on 23 October. Each item links to its primary source, and all sources were accessed on 24 October 2026.

Summary

PHP runs on 69.3% of websites whose server-side language is known (W3Techs). The two flaws, CVE-2026-109618 and CVE-2026-109619, are both rated 9.2 under CVSS v4.0 and allow an unauthenticated attacker to execute code on a PHP web server (PHP). On Apache with mod_php, a single request suffices, and the attack runs before any application code. Both flaws follow one pattern: a fatal error, typically out of memory (OOM), aborts a request while request-owned memory is half-built or still referenced from global state, and cleanup code or the next request on the same worker then uses that invalid memory. PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 contain the fix, minimal source backports exist for 7.4, 8.0 and 8.1, and PHP 7.3 and older receive nothing.

The two vulnerabilities

PHP aborts a request that exceeds memory_limit by calling longjmp(), which leaves the current context without running the code that keeps request memory consistent (GHSA-w8hw-w9fx-j79w). In CVE-2026-109618, an allocation fails while request memory is already reachable but not yet initialized, so request shutdown later reads or frees memory that may still hold attacker-controlled data from earlier allocations (CERT-EU). The failed allocation need not be related to the corrupted memory. Attackers can force the OOM cheaply during multipart upload parsing, since multipart requests without a usable declared length pass the initial post_max_size check, a single part may carry an unlimited number of headers that occupy far more memory in PHP than on the wire, and empty file controls create metadata arrays without counting toward max_file_uploads. The PHP team validated a full remote exploit against mod_php with default limits, whereas PHP-FPM, FrankenPHP and LSAPI are considered susceptible from source analysis only.

CVE-2026-109619 is a use-after-free in which error, session, object or extension state held by a long-lived worker points into memory of a previous request (GHSA-6wmf-4rv5-p3rp). The stale state is produced when a fatal error, such as a parse failure, an uncaught error, a failed require, an execution timeout or an OOM, interrupts the reset of that state. It is consumed by operations that run before normal request initialization, namely warnings raised while applying INI settings (even when errors are neither displayed nor logged) and session upload progress handling. Wiz Research describes concrete variants, including a fatal-error backtrace pointer (EG(last_fatal_error_backtrace)) left uncleared after an OOM, and a session identifier (PS(id)) left pointing to freed memory, which returns reclaimed heap contents to the attacker in the PHPSESSID cookie (Wiz). According to Wiz, every PHP version released in the last decade is affected by at least one of the issues.

Discovery and disclosure

Wiz Research found the first flaw on 19 August 2026, confirmed unauthenticated code execution against Drupal on 20 August and against WordPress on 21 August, and reported to the PHP security team on 24 August (Wiz). PHP acknowledged the reports on 21 September and began a coordinated fix. Wiz states that the work used its Wiz Atlas tool together with Gemini 4 Argon and GPT-5.6 Sol, and credits Gemini 4 Argon with contributions to discovery, exploit development, attack detection and patch validation. The relative contribution of each model and of the human researchers cannot be determined from the public reports. The PHP advisories credit four reporters (lcfr-hax, sagitzadik-wiz, tomash-areion and amyb-oai).

Disclosure was planned for 22 October, but details leaked on social media on 20 October (watchTowr). PHP announced the same day a security release for 21 October at 14:00 UTC and reserved the right to release earlier (PHP). Linux distributions and LTS vendors had received the patches in advance (Fig. 1).

The fix

The patch for CVE-2026-109618 removes longjmp() from OOM handling (GHSA-w8hw-w9fx-j79w). When a request exceeds its memory limit, PHP now raises a delayed "soft" OOM at the next safe point of the virtual machine, where request state is consistent, so shutdown no longer encounters half-initialized memory. If memory use reaches a second, higher threshold before that point, PHP ends the process immediately with _exit(), which skips shutdown entirely. Memory limiting therefore keeps working, while the abort no longer interrupts code that is building request state.

The patch for CVE-2026-109619 resets a wider set of request-owned state, since, in the words of the advisory, this state "must not survive into operations that precede normal initialization" (GHSA-6wmf-4rv5-p3rp). The advisory does not list the individual code changes. Updated installations must restart every PHP worker, because running workers keep the old code (watchTowr).

Exploitation

Amazon honeypots logged an exploit attempt on 17 October, four days before disclosure, and Cloudflare saw attempts rise from tens of thousands within 45 minutes of the 21 October release to millions by early 22 October (The Hacker News). watchTowr reported exploitation against its honeypot network on 21 October (watchTowr). Sophos and Arctic Wolf reported attempts to install a Mirai botnet variant, which had failed so far, and Wordfence and others reported scanning and probing without confirmed code execution (The Hacker News). These figures come from a news report that cites the vendors and require validation against the vendors' own publications. On 22 October, neither CVE was listed in the Known Exploited Vulnerabilities catalogue of the US Cybersecurity and Infrastructure Security Agency (CISA) (watchTowr).

Affected versions and interim measures

Among websites running PHP, 65.4% use PHP 8, 26.8% PHP 7, 7.7% PHP 5 and 0.1% PHP 4 (W3Techs). At least 7.8% of PHP websites therefore run a major version for which no fix exists, and PHP 7 sites can be patched only on 7.4 through a source backport or a vendor package (Fig. 2). PHP 8.2 reaches end of life on 31 December 2026 (PHP).

PHP states that no configuration change makes an installation safe, and lists measures that only reduce exposure (PHP). For CVE-2026-109618, these are memory_limit=-1 set so that applications cannot override it, post_max_size of 8M (no uploads) or 32M (uploads), and a container or cgroup memory limit in place of RLIMIT_AS or RLIMIT_DATA, since the latter make mmap() fail and thereby trigger the vulnerable path. The memory_limit=-1 setting is incomplete for the same reason, as a failed mmap() can still reach longjmp() (GHSA-w8hw-w9fx-j79w). For CVE-2026-109619, PHP recommends session.upload_progress.enabled=0 in php.ini or the FPM pool followed by a restart of every worker, fatal_error_backtraces=0 on PHP 8.5, and the removal of invalid per-request INI settings; ini_set() and .user.ini do not work here because they apply after request parsing, and hiding diagnostics with error_reporting, display_errors or @ does not help.

A third vulnerability

On 23 October, PHP disclosed CVE-2026-115560, a further code execution path that the 21 October releases do not fix (PHP). It requires an unusual setup, in which an application configures session.serialize_handler as php_binary or php_serialize, switches it to php with ini_set() before session_start(), and keeps session upload progress enabled. PHP will fix it in the next regular release rather than out of band, and recommends session.upload_progress.enabled=0 until then, the same setting already listed for CVE-2026-109619. No exploitation of this flaw had been reported by 24 October (The Hacker News).
